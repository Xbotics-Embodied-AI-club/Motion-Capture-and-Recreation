# Motion-Capture-and-Recreation（身外化身 · 动作捕捉与复刻）

## 一、项目简介

**身外化身**是一套基于单目 RGB 视频的人体动作捕捉与机器人动作复刻系统。系统以普通摄像头或已有视频为输入，结合人体检测、二维姿态估计、WHAM 三维人体运动重建与 GMR 逆运动学重映射，将视频中人的动作转换为目标机器人的关节运动，并在 MuJoCo 中进行可视化回放，输出关节角序列与演示视频。

项目以灵龙 2.0（LingLong 2.0）为默认目标机器人，围绕“看见人的动作—理解三维运动—适配机器人结构—展示复刻结果”构建完整处理流程。例如，用户在摄像头前挥手、叉腰、抬腿或转身后，系统提取对应的人体运动，并生成机器人形态下的动作表达。

项目希望降低动作采集与机器人动画制作的门槛：使用常见 RGB 摄像头，减少对穿戴式传感器、标记点和专用动捕场地的依赖；通过参数化人体与机器人运动学模型之间的映射，使同一段人体动作能够进一步用于仿真展示、动作素材制作和机器人运动研究。

当前工作的重点是打通从视觉输入到机器人运动数据的端到端链路，并通过模型、权重、机器人资产与运行环境的统一封装，提高部署和复现的便利性。摄像头模式采用持续采集、分阶段推理与动作更新的方式运行，其实际响应速度取决于硬件、模型计算量和处理策略。

## 二、技术路线

### 2.1 整体处理流程

> 输入视频 / 摄像头 → 人体检测与跟踪 → 二维姿态估计及图像特征提取 → WHAM 三维运动重建 → 人体运动表示适配 → GMR IK 重映射 → MuJoCo 可视化 → CSV 与演示视频

| 阶段 | 主要组件 | 核心任务 | 输出 |
| --- | --- | --- | --- |
| 视频输入 | 摄像头、视频解码模块 | 获取图像帧及其顺序信息 | 图像序列 |
| 人体定位 | YOLO 等检测组件 | 定位目标人物，组织连续的人体观测 | 人体框及关联信息 |
| 视觉表征 | ViTPose、HMR2 图像编码模块 | 提取二维关键点与人体外观特征 | 关键点序列、图像特征 |
| 三维重建 | WHAM | 融合时序运动线索与视觉特征，恢复三维人体运动 | 人体姿态、形状及根部运动相关结果 |
| 表示适配 | 项目数据转换模块 | 统一关节定义、坐标系、尺度与旋转表示 | GMR 所需的人体部位位姿 |
| 动作重映射 | GMR、IK 求解器 | 在机器人结构和关节约束下拟合人体动作 | 机器人关节配置序列 |
| 展示与导出 | MuJoCo、数据与视频写出模块 | 更新机器人姿态，回放和记录结果 | 关节角 CSV、MP4 视频 |

### 2.2 输入与人体视觉特征提取

系统支持已有视频和摄像头两类输入。视频输入适合重复实验与结果对比；摄像头输入适合现场演示和交互式动作采集。

每帧图像首先经过人体检测，确定目标人物的位置，并以人体区域组织后续处理。ViTPose 估计肩、肘、髋、膝等二维关键点，描述人体在图像中的几何结构；HMR2 图像编码模块提取人体外观特征，为三维重建提供补充线索。前者主要回答“关节在图像中的哪里”，后者提供帮助判断人体姿态和形状的视觉信息。

关键点和图像特征按照时间顺序送入后续模块。连续帧中的运动变化能够帮助系统缓解单帧深度歧义，但遮挡、出画、光照变化和检测误差仍会影响重建质量。

### 2.3 WHAM：从二维视频恢复三维人体运动

**WHAM（World-grounded Humans with Accurate Motion）**是一种从单目视频恢复三维人体运动的方法。它关注连续动作在时间上的一致性，以及人体在世界坐标系中的运动表达，而不只是对每张图像分别估计一个姿态。[1][2]

其基本思路是结合两类互补信息：一类是二维关键点序列所描述的运动结构，另一类是图像编码器提取的外观特征。通过时序建模，WHAM 利用相邻帧的上下文推断三维姿态，减少单帧估计中容易出现的朝向歧义和运动不连续问题。[1]

重建结果采用参数化人体表示。**WHAM 原生基于 SMPL 人体模型**，以姿态参数描述关节旋转，以形状参数描述体型差异，并结合根部朝向、平移等信息表达人体运动。由此可以进一步计算三维关节位置与人体网格，为机器人重映射提供几何依据。[1][2]

WHAM 还利用脚部接触等运动线索改善全局运动估计，减轻脚底滑动等问题。对于存在相机运动的视频，系统可结合视觉里程计提供相机运动信息；本项目链路中的 DPVO 属于此类可选组件。关闭相机运动估计时，应结合固定机位等使用条件解释全局轨迹结果。[1][2]

在本项目中，WHAM 承担“视觉观测到三维人体运动”的转换。项目现有处理方案使用 16 帧时序窗口组织推理；窗口长度属于项目运行配置，不代表 WHAM 方法固定只能处理 16 帧。时序信息有助于保持动作连续，也会与推理开销共同影响摄像头模式的响应延迟。

**人体表示适配是 WHAM 与 GMR 之间的重要接口。** SMPL 与 SMPL-X 的模型结构和关节定义不同，不能仅通过更改名称完成转换。项目应以实际转换代码为准，将重建结果整理为重映射所需的人体部位位置和朝向，并核对关节对应关系、坐标轴方向、长度单位及旋转格式。

### 2.4 GMR IK：从人体运动映射到机器人关节运动

**GMR（General Motion Retargeting，通用动作重映射）**用于将人体动作转换为不同人形机器人的运动表示。其 IK 求解建立在 Mink 与 MuJoCo 等工具之上，人体输入可以组织为各身体部位的三维全局位置与旋转。[3]

人体与机器人在肢体比例、关节数量、转轴方向和活动范围上存在差异。因此，系统需要建立人体部位与机器人部位之间的对应关系，再求解能够尽量保留动作特征的机器人姿态。

**IK（Inverse Kinematics，逆运动学）**回答的问题是：已知希望机器人手、脚或躯干到达的位置和朝向，各关节应当转到什么角度？与之相对，正向运动学是给定关节角后计算身体部位的位姿。

重映射过程可以分为四个环节：

1. **建立部位对应关系。** 将人体骨盆、躯干、手部、足部等关键部位，与灵龙 2.0 模型中的对应连杆建立关联，确定动作跟踪目标。
2. **进行尺度与位姿对齐。** 根据人体和机器人的结构差异调整目标尺度与偏移，统一坐标系和旋转约定，避免直接使用人体尺寸导致目标超出机器人可达范围。
3. **构建加权跟踪任务。** 为关键部位的位置和朝向设置拟合目标与权重，表达不同部位的跟踪优先级。
4. **迭代求解关节配置。** 利用机器人运动学模型和雅可比矩阵逐步降低任务误差，并按实际配置施加关节位置、速度等约束，得到对应帧的机器人姿态。[3]

以“抬腿”为例，人体重建模块提供腿部运动与躯干姿态；重映射模块则依据机器人腿长、髋膝踝结构及关节限制，求解能够表达相似动作的关节组合。机器人最终姿态可能与人体存在差别，这是不同机械结构下约束求解的结果。

从概念上看，重映射是在“尽量接近人体目标位姿”和“满足机器人运动学约束”之间求取折中。连续处理时，可以使用前一帧的求解状态作为后续迭代的起点，帮助保持动作衔接；具体平滑效果仍取决于输入质量、任务权重和求解配置。

需要区分运动学复刻与动力学控制：IK 得到结构允许的姿态，并不自动保证机器人在真实环境中保持平衡、满足力矩限制或安全执行。若后续扩展到真机，还需要动力学验证、接触处理、控制器设计与实机测试。

### 2.5 MuJoCo 可视化与工程集成

系统将重映射得到的关节配置写入 MuJoCo 中的灵龙 2.0 模型，按时间顺序更新机器人姿态并生成画面。通过回放，可以直观检查动作方向、关节对应关系、姿态连续性和明显的穿模现象。

MuJoCo 在当前链路中主要用于机器人模型加载与动作可视化。仅完成姿态更新和视频渲染，不能据此认定已经通过动力学稳定性验证。

工程实现上，项目围绕统一入口组织采集、推理、重映射、渲染与导出，并使用 Docker 封装依赖、模型权重和机器人资产。摄像头模式下，需要协调采集速度与处理速度：采用异步写盘、合理采样和检测结果复用等策略可以减少部分开销，但端到端更新频率仍应以实际运行测量为准。

## 三、最终产出

### 3.1 机器人关节角序列

系统输出 `live_motion.csv`，记录灵龙 2.0 的机器人关节运动数据。按当前 README 的定义，文件包含 **37 列关节角序列**，可用于动作回放、数值分析与后续数据处理。

每行对应一个输出动作帧，每列对应约定的机器人关节。实际使用时，应以导出代码或 CSV 表头为准确认关节名称、列顺序、角度单位、采样间隔及有效帧数，避免将人体关节编号直接当作机器人关节编号。若另行增加时间戳或帧号，应在格式说明中区分辅助字段与这 37 列关节数据。

### 3.2 MuJoCo 演示视频

系统输出 MP4 格式的机器人动作演示视频，展示重映射后机器人随时间变化的运动过程。视频可用于项目汇报、结果对比和动作复刻效果检查；摄像头原始视频是否同时记录，以运行配置为准。

展示时建议说明输入类型、处理帧率和回放帧率，使观看者能够区分实际响应速度与视频播放速度。动作相似度可以通过挥手、叉腰、抬腿、转身等具有明确身体结构变化的动作进行直观观察。

### 3.3 可复现的运行交付

除动作数据和视频外，项目通过代码、机器人模型资产、运行参数说明与 Docker 镜像形成可复现交付。核心成果是建立一条可运行、可回放、可导出的“人体视频到机器人动作”处理链路，为后续优化三维重建精度、动作连续性、运行效率以及真机控制研究提供基础。
